Pipeline Redesoft · tutorial

Redesoft no Google Cloud

Passo a passo para levar os dados do B2Click para o BigQuery e publicar dashboards no Looker Studio com acesso restrito, em dois ambientes: Airflow no PC da TI (ambiente 1) e agendador do Google sem servidor (ambiente 3).

Comandos para o PowerShell do Windows. Região: São Paulo (southamerica-east1). Onde aparece redesoft-dados, use o ID do projeto que vocês criarem.

Os dois ambientes

Ambiente 1

Airflow no PC, dados no BigQuery

PC da TI (Docker + Airflow) → API B2Click → BigQuery → Looker Studio

Igual a hoje, mudando só o destino dos dados. Custo de nuvem perto de zero, mas o PC precisa estar ligado às 02:00. Bom para começar e testar.

Ambiente 3 · recomendado

Cloud Run + Scheduler

Agendador do Google (02:00) → tarefa no Cloud Run → API B2Click → BigQuery → Looker Studio

Nenhum computador da empresa precisa ficar ligado. A tarefa liga, busca, grava, organiza e desliga. Custo perto de zero no volume atual.

Ordem sugerida

Parte 0 → Parte 1 (testar com o Airflow que já conhecem) → Parte 2 (levar para o Google) → Parte 3 (dashboards). Os dois ambientes usam o mesmo projeto, os mesmos dados e as mesmas tabelas: a Parte 2 só troca quem dispara a carga.

Adaptação do código (pré-requisito)

Status: pronta (25/11/2026)

O pipeline agora grava no PostgreSQL ou no BigQuery, escolhido pela variável DESTINO. A lógica que já funcionava (limite de chamadas da API, divisão por dias, regras de encerrante × aferição × venda) foi reaproveitada. Testado num emulador local do BigQuery com dados reais de 01/11/2026: os totais bateram com o PostgreSQL (34 postos, 232.172 litros, R$ 1.353.730). Ainda não foi rodado numa conta real do Google Cloud.

O que mudaComo fica
Gravação dos dados brutosOpção DESTINO=bigquery (plugins/redesoft/destino_bigquery.py). Cada CSV do B2Click vira uma tabela do dataset raw_b2click, uma coluna de texto por campo, particionada por data_ref. Recarregar um dia ou um mês substitui só aquela parte; campos novos da API entram sozinhos.
Arquivos originais (bronze)BRONZE_URI=gs://<bucket>/bronze: os CSVs vão para o Cloud Storage em vez da pasta data/bronze.
Transformações (dbt)Os mesmos modelos rodam nos dois bancos: as conversões escolhem o dialeto sozinhas (dbt/macros/b2click.sql). Perfil bigquery em dbt/profiles.yml, escolhido por DBT_TARGET=bigquery.
Tarefa do Cloud Run (só ambiente 3)Pasta cloudrun/: Dockerfile e executar.py, que roda as 12 extrações e depois o dbt build. Variáveis opcionais: DATA_INICIO/DATA_FIM (histórico), FONTES (só algumas), PULAR_DBT=1.

Parte 0 · Preparar o Google Cloud

Feito uma vez, vale para os dois ambientes. Tempo: ~1 hora.

  1. Criar o projeto e ligar a cobrança

    • Acesse console.cloud.google.com com a conta Google da empresa.
    • Crie um projeto (ex.: redesoft-dados) e vincule uma conta de faturamento com cartão. Mesmo dentro das cotas gratuitas, o BigQuery e o Cloud Run exigem faturamento ativo.
    • Faturamento → Orçamentos e alertas: crie um orçamento de R$ 50/mês com alerta por e-mail em 50%, 90% e 100%. Assim qualquer surpresa aparece cedo.

  2. Instalar a linha de comando do Google (gcloud)

    Baixe o instalador para Windows em cloud.google.com/sdk/docs/install. Depois, num PowerShell novo:

    PowerShell
    gcloud init

    Ele abre o navegador para o login e pergunta qual projeto usar. Escolha o projeto criado no passo 1.

  3. Definir os nomes usados nos comandos

    Rode no começo de cada sessão do PowerShell. Troque os valores se usarem outros nomes; o nome de bucket precisa ser único no mundo.

    PowerShell
    $PROJETO = "redesoft-dados"
$REGIAO  = "southamerica-east1"
$BUCKET  = "redesoft-dados-bronze"
$SA      = "pipeline-redesoft@$PROJETO.iam.gserviceaccount.com"

  4. Ativar os serviços

    PowerShell
    gcloud services enable bigquery.googleapis.com storage.googleapis.com run.googleapis.com cloudscheduler.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com

    Os quatro últimos só são usados no ambiente 3, mas ativar agora não custa nada.

  5. Criar os conjuntos de dados no BigQuery

    Os mesmos três níveis de hoje: dados brutos, limpos e prontos para os dashboards.

    PowerShell
    bq --location=$REGIAO mk --dataset "${PROJETO}:raw_b2click"
bq --location=$REGIAO mk --dataset "${PROJETO}:staging"
bq --location=$REGIAO mk --dataset "${PROJETO}:gold"

  6. Criar o bucket dos arquivos originais

    PowerShell
    gcloud storage buckets create "gs://$BUCKET" --location=$REGIAO --uniform-bucket-level-access

    O bucket nasce privado. Não ative acesso público.

  7. Criar a conta de serviço do pipeline

    É o "usuário" que o pipeline usa para gravar. Ela recebe só as permissões necessárias.

    PowerShell
    gcloud iam service-accounts create pipeline-redesoft --display-name="Pipeline Redesoft"
gcloud projects add-iam-policy-binding $PROJETO --member="serviceAccount:$SA" --role="roles/bigquery.dataEditor"
gcloud projects add-iam-policy-binding $PROJETO --member="serviceAccount:$SA" --role="roles/bigquery.jobUser"
gcloud storage buckets add-iam-policy-binding "gs://$BUCKET" --member="serviceAccount:$SA" --role="roles/storage.objectAdmin"

  8. Limitar o gasto com consultas (recomendado)

    No console: IAM e administrador → Cotas, filtre por BigQuery API · Query usage per day e defina um teto, por exemplo 200 GB por dia. Uma consulta pesada feita por engano não passa disso.

Parte 1 · Ambiente 1: Airflow no PC gravando no BigQuery

Requer a Parte 0. Tempo: ~1 hora.

  1. Gerar a chave da conta de serviço

    O Airflow no PC precisa de um arquivo de chave para se identificar no Google. Ele fica numa pasta secrets, fora do git.

    PowerShell
    cd "$env:USERPROFILE\Desktop\pipeline redesoft"
New-Item -ItemType Directory -Force secrets | Out-Null
gcloud iam service-accounts keys create secrets\gcp-pipeline.json --iam-account=$SA
    Cuidado com esse arquivo

    Quem tiver a chave grava no BigQuery em nome do pipeline. Não envie por e-mail nem coloque no git (a pasta secrets/ vai para o .gitignore). Se a organização bloquear a criação de chaves, o erro cita iam.disableServiceAccountKeyCreation: nesse caso, pule direto para o ambiente 3, que não usa chave.

  2. Ajustar o .env

    Acrescente (ou troque) estas linhas. As credenciais do B2Click continuam as mesmas.

    .env
    DESTINO=bigquery
DBT_TARGET=bigquery
BQ_PROJETO=redesoft-dados
BQ_LOCAL=southamerica-east1
BRONZE_URI=gs://redesoft-dados-bronze/bronze
GOOGLE_APPLICATION_CREDENTIALS=/opt/airflow/secrets/gcp-pipeline.json

  3. Subir o Airflow com a nova versão

    O docker-compose.yml já monta a pasta secrets (somente leitura), e a imagem já traz o dbt-bigquery e as bibliotecas do Google.

    PowerShell
    docker compose up -d --build

  4. Testar com poucos dias

    Em localhost:8080, abra a DAG b2click_diario → Trigger DAG w/ config:

    config
    {"data_inicio": "2026-11-20", "data_fim": "2026-11-23"}

    Depois confira no BigQuery (console → BigQuery → editor de consultas):

    SQL
    select data, count(distinct cod_empresa) as postos, round(sum(quantidade)) as litros
from `redesoft-dados.gold.fct_vendas_diario`
where especie = 'COMBUSTIVEL'
group by data order by data;

    Os números devem bater com o PostgreSQL local para os mesmos dias.

  5. Garantir o PC ligado às 02:00

    • Windows → Configurações → Energia: suspensão em Nunca quando ligado na tomada.
    • Docker Desktop → Settings → General: marque Start Docker Desktop when you sign in.
    • Depois de queda de energia ou atualização do Windows, alguém precisa entrar no usuário para o Docker abrir. Esse é o principal motivo para migrar ao ambiente 3.

Parte 2 · Ambiente 3: Cloud Run + Scheduler, sem servidor

Requer a Parte 0 e o Docker Desktop no PC, só para montar a imagem. Tempo: ~2 horas.

  1. Guardar o token do B2Click no cofre de segredos

    • Console → Segurança → Secret Manager → Criar secret.
    • Nome: b2click-token. Valor: o token. Local: regional, São Paulo.
    • Faça pelo console, não pela linha de comando, para o token não ficar no histórico do PowerShell.

    Depois dê à conta de serviço permissão de ler o segredo:

    PowerShell
    gcloud secrets add-iam-policy-binding b2click-token --member="serviceAccount:$SA" --role="roles/secretmanager.secretAccessor"

  2. Criar o repositório de imagens

    PowerShell
    gcloud artifacts repositories create pipeline --repository-format=docker --location=$REGIAO
gcloud auth configure-docker "$REGIAO-docker.pkg.dev"

  3. Montar e enviar a imagem da tarefa

    Com o Docker Desktop aberto, na pasta do projeto:

    PowerShell
    $IMAGEM = "$REGIAO-docker.pkg.dev/$PROJETO/pipeline/redesoft:v1"
docker build -f cloudrun/Dockerfile -t $IMAGEM .
docker push $IMAGEM

    A cada mudança no código, repita com uma versão nova (v2, v3...) e atualize a tarefa no passo 4 com gcloud run jobs update.

  4. Criar a tarefa no Cloud Run

    1 vCPU, 2 GB de memória e até 3 horas por execução, para dar tempo de esperar a cota da API do B2Click virar a hora. Troque ENTIDADE e USUARIO pelos valores do .env.

    PowerShell
    gcloud run jobs create redesoft-diario `
  --image=$IMAGEM --region=$REGIAO --service-account=$SA `
  --cpu=1 --memory=2Gi --task-timeout=3h --max-retries=1 `
  --set-env-vars="DESTINO=bigquery,BQ_PROJETO=$PROJETO,BQ_LOCAL=$REGIAO,BRONZE_URI=gs://$BUCKET/bronze,B2CLICK_ENTIDADE=ENTIDADE,B2CLICK_USUARIO=USUARIO" `
  --set-secrets="B2CLICK_TOKEN=b2click-token:latest"

  5. Rodar uma vez para testar

    PowerShell
    gcloud run jobs execute redesoft-diario --region=$REGIAO --wait

    Sem datas, ela carrega os últimos 3 dias. Os logs ficam em Console → Cloud Run → Jobs → redesoft-diario → Execuções. Confira os números com a consulta da Parte 1.

    Não rode junto com o Airflow local

    A API do B2Click aceita 10 chamadas por hora por endpoint. Se o ambiente 1 ainda estiver ativo, pause a DAG b2click_diario no PC antes deste teste.

  6. Agendar para todo dia às 02:00

    Mais fácil pelo console: Cloud Run → Jobs → redesoft-diario → Gatilhos → Adicionar gatilho do Scheduler, frequência 0 2 * * *, fuso America/Sao_Paulo. Ou pela linha de comando:

    PowerShell
    gcloud run jobs add-iam-policy-binding redesoft-diario --region=$REGIAO --member="serviceAccount:$SA" --role="roles/run.invoker"
gcloud scheduler jobs create http redesoft-02h `
  --location=$REGIAO --schedule="0 2 * * *" --time-zone="America/Sao_Paulo" `
  --uri="https://run.googleapis.com/v2/projects/$PROJETO/locations/$REGIAO/jobs/redesoft-diario:run" `
  --http-method=POST --oauth-service-account-email=$SA

  7. Receber e-mail quando falhar

    • Console → Monitoring → Alertas → Criar política.
    • Métrica: Cloud Run Job → Completed executions, filtrando result = failed e o job redesoft-diario. Condição: qualquer valor acima de 0.
    • Canal de notificação: e-mail da TI.

  8. Carregar o histórico

    Para meses anteriores, rode a tarefa com as datas. Cada mês consome cerca de 5 chamadas por endpoint da cota de 10 por hora; a tarefa espera sozinha quando a cota acaba.

    PowerShell
    gcloud run jobs execute redesoft-diario --region=$REGIAO --update-env-vars="DATA_INICIO=2026-01-01,DATA_FIM=2026-10-31" --wait

  9. Desligar o ambiente 1

    Depois de uma semana com o agendamento funcionando, pause as DAGs no Airflow local. O Docker do PC pode continuar como ambiente de testes.

Parte 3 · Looker Studio e controle de acesso

Funciona igual para os dois ambientes, porque os dois gravam no mesmo BigQuery.

  1. Conectar o BigQuery

    • Acesse lookerstudio.google.com → Criar → Relatório.
    • Adicionar dados → BigQuery → Meus projetos → redesoft-dados → gold → escolha a tabela (comece por fct_vendas_diario).
    • Repita para fct_conciliacao_tanque_diario, fct_afericao_bico_turno, fct_pagamentos_diario e dim_empresa.

  2. Configurar cada fonte de dados

    • Credenciais: do proprietário. Quem vê o dashboard não precisa de acesso ao BigQuery.
    • Atualização dos dados: a cada 4 horas. A carga roda de madrugada; atualizar mais vezes só gasta consultas.
    • Use sempre as tabelas do gold, que são resumidas. Evite ligar dashboards nas tabelas do raw_b2click.

  3. Compartilhar só com quem pode ver

    • No relatório: Compartilhar → Convidar pessoas, com os e-mails (ou um Grupo do Google, como "diretoria").
    • Em Gerenciar acesso, deixe o link como Restrito (nunca "Qualquer pessoa com o link").
    • Desmarque a opção de visualizadores baixarem, imprimirem e copiarem, se não quiserem que os dados saiam do dashboard.
    • Cada pessoa entra com conta Google. Quem usa e-mail de outro provedor pode criar uma conta Google com o próprio e-mail da empresa, sem criar Gmail.

  4. Cada gerente vê só o próprio posto

    Crie uma tabela de permissões (quem vê qual posto) e uma visão que junte os dados com ela:

    SQL
    create table `redesoft-dados.gold.permissoes` (email string, cod_empresa int64);

insert into `redesoft-dados.gold.permissoes` values
  ('gerente.bessa@empresa.com.br', 22),
  ('diretoria@empresa.com.br', 1), ('diretoria@empresa.com.br', 3);  -- uma linha por posto

create or replace view `redesoft-dados.gold.vw_vendas_por_usuario` as
select v.*, p.email
from `redesoft-dados.gold.fct_vendas_diario` v
join `redesoft-dados.gold.permissoes` p using (cod_empresa);

    No Looker Studio, use a visão como fonte de dados e, em Editar fonte de dados, ative Filtrar por e-mail escolhendo o campo email. Cada pessoa passa a ver só as linhas com o e-mail dela. Os e-mails acima são exemplos.

  5. Portal com a cara da empresa (opcional)

    Crie um site no Google Sites (gratuito), insira os relatórios por Inserir → Looker Studio e restrinja o site às mesmas pessoas. O controle de acesso continua sendo o do Looker Studio: o dashboard embutido só abre para quem está logado numa conta autorizada.

Parte 4 · Backup dos programas

Um bucket separado, com versionamento: se um arquivo for apagado ou corrompido, a versão anterior continua lá. Para arquivos leves, o custo é de centavos por mês.

PowerShell
$BACKUP = "redesoft-dados-backup-programas"
gcloud storage buckets create "gs://$BACKUP" --location=$REGIAO --uniform-bucket-level-access --default-storage-class=NEARLINE
gcloud storage buckets update "gs://$BACKUP" --versioning
gcloud storage rsync "D:\Programas" "gs://$BACKUP/programas" --recursive
  • Troque D:\Programas pela pasta real. Agende a última linha no Agendador de Tarefas do Windows (diário ou semanal).
  • Nearline é mais barato para arquivos que raramente são lidos. Há cobrança mínima de 30 dias por arquivo, irrelevante para backup.
  • Para não acumular versões para sempre: no console, Cloud Storage → bucket → Ciclo de vida, regra para apagar versões antigas com mais de 90 dias.

Problemas comuns

SintomaCausa provávelO que fazer
Log mostra "limite de requisições/hora atingido; aguardando"Cota de 10 chamadas/hora da API do B2Click, dividida com outros usosNada: a tarefa espera a hora virar. Se acontecer todo dia, verifique se outro sistema (relatórios antigos, ambiente 1) chama a API no mesmo horário.
Access Denied ao gravar no BigQueryConta de serviço sem papelRefaça o passo 7 da Parte 0 e confira se o projeto em BQ_PROJETO é o mesmo.
Tarefa termina por tempo (timeout)Carga histórica longa esperando a cotaDivida o período em blocos de 1 a 2 meses ou aumente --task-timeout.
API do B2Click recusa a conexão vinda do GoogleA Redesoft pode liberar só IPs conhecidosConfirme com a Redesoft. Se exigir IP fixo, o Cloud Run precisa de Cloud NAT com IP reservado (≈ US$ 30–35/mês).
Dashboard mostra dados de ontem à tardeCache do Looker StudioBotão Atualizar dados no relatório, ou reduza o intervalo de atualização da fonte.
Datas com um dia de diferençaFuso horárioAgendamentos sempre em America/Sao_Paulo. As datas do B2Click já vêm no horário de Brasília.
Base: o pipeline do projeto "pipeline redesoft" (extrator B2Click, regras de conciliação e modelos gold), já preparado para o BigQuery e testado num emulador local. Os comandos do Google Cloud CLI foram conferidos contra a sintaxe atual, mas ainda não executados numa conta real: rode primeiro com poucos dias de dados.
