Pipeline Redesoft na AWS

Quanto custa e como levar o pipeline (B2Click → Airflow → PostgreSQL → Power BI) do computador da TI para a nuvem, na região de São Paulo.

Preços: tabela oficial da AWS para sa-east-1, consultada em 25/11/2026, sob demanda, 730 h/mês. Conversão a R$ 5,85 por US$ (cotação de meados de novembro/2026); a fatura da AWS vem em dólar.

Resumo

≈ US$ 25/mêsAWS, máquina ligada só na carga (≈ R$ 150)
≈ US$ 0–5/mêsGoogle BigQuery + Cloud Run (estimativa)
≈ US$ 209/mêsAWS com servidores 24 h e banco gerenciado (≈ R$ 1.220)

O pipeline trabalha cerca de 30 minutos por dia. Quase todo o custo das opções com servidores 24 h é máquina ociosa: o armazenamento é só 13% do total. Por isso há duas opções mais baratas: ligar a máquina só na janela da carga (sem mudar o código) ou usar serviços cobrados por uso no Google Cloud (com 2 a 3 dias de adaptação). O volume de dados é pequeno para a nuvem (≈ 30 GB por ano).

O código é o mesmo que já roda na máquina da TI. Mudam só os endereços: o bronze passa a ser gravado no S3, o banco passa a ser o RDS e o Power BI aponta para o RDS em vez de localhost.

Opções de custo

Mais simples · 24 h

A · Tudo numa máquina

US$ 101 /mês · ≈ R$ 590

Airflow e PostgreSQL no mesmo servidor EC2, como hoje no PC. Backup feito por snapshot do disco. Se o servidor cair, o banco cai junto.

Disco de 100 GB: ~85 GB para dados, cerca de 2,5 anos no ritmo atual. Ampliável sem desligar, a US$ 15,20 por mês para cada 100 GB a mais.

Recomendada

B · EC2 + RDS

US$ 209 /mês · ≈ R$ 1.220

Banco gerenciado pela AWS: backup diário com 7 dias de retenção, atualização de versão e recuperação sem trabalho manual. Com RDS menor (db.t4g.small), cai para ≈ US$ 159.

Alta disponibilidade

C · RDS Multi-AZ

US$ 331 /mês · ≈ R$ 1.940

Banco duplicado em dois datacenters de São Paulo, com troca automática em caso de falha. Só vale se os dashboards forem críticos durante o dia todo.

Possível custo extra: gateway do Power BI ≈ US$ 43/mês

Se o banco ficar fechado à internet (o recomendado), o Power BI Service precisa de um gateway de dados numa máquina Windows sempre ligada. Pode ser uma máquina da empresa que já fica ligada (custo zero) ou uma EC2 Windows t3.small (US$ 0,052/h + 30 GB de disco ≈ US$ 43/mês). Relatos de atualização direta do Power BI no RDS, sem gateway, falham com frequência por certificado SSL.

Como reduzir
  • Compromisso de 1 ano (Savings Plan na EC2, instância reservada no RDS): em geral 25–35% de desconto, sem pagamento adiantado. Faça só depois de 1–2 meses estável.
  • Ligar a EC2 só na hora da carga: o pipeline leva ~30 min por dia. Ligando e desligando pelo EventBridge Scheduler (2 h/dia), o servidor cai de US$ 78 para ≈ US$ 6,50 e o cenário B fica perto de US$ 137. A interface do Airflow fica indisponível no resto do dia.
  • Região da Virgínia (us-east-1) é ~35% mais barata, mas os dados da rede saem do Brasil. Recomendamos ficar em São Paulo.
  • Banco menor: manter no PostgreSQL só os últimos 90 dias da camada raw (o histórico completo fica no S3) segura o disco do RDS em 50 GB.

Duas opções mais baratas

Nas opções acima, o servidor e o banco ficam ligados 24 horas para um trabalho de 30 minutos. Estas duas evitam pagar pela ociosidade.

Passo a passo da migração

Os passos abaixo valem para as opções na AWS (A, B, C e D). Na opção D, o passo 4 (RDS) sai e o banco fica no próprio servidor; o passo 5 ganha o liga/desliga no EventBridge Scheduler.

A ordem importa: cada passo depende do anterior. Cálculo de esforço: 2 a 3 dias de trabalho da TI, com o pipeline local rodando em paralelo até a nuvem ser validada.

  1. Conta e controle de custos

    • Conta AWS da empresa, com MFA no usuário raiz e um usuário IAM administrador para o dia a dia.
    • Região South America (São Paulo) – sa-east-1 em tudo.
    • AWS Budgets: alerta por e-mail em US$ 250/mês (ou o valor escolhido).

  2. Repositório do código

    • Criar um repositório privado (GitHub ou similar) e enviar o projeto. Hoje o código só existe no PC da TI.
    • O arquivo .env continua fora do git. Na AWS, o token do B2Click fica no SSM Parameter Store (criptografado, sem custo no nível padrão).

  3. Bucket S3 do bronze

    • Bucket privado (bloqueio de acesso público ligado), criptografia padrão.
    • Regra de ciclo de vida: mover para Glacier Instant Retrieval após 90 dias (barateia o histórico).

  4. Banco RDS PostgreSQL

    • PostgreSQL 16, db.t4g.medium, gp3 100 GB, criptografado, backup automático de 7 dias.
    • Acesso público desligado; grupo de segurança aceitando só a EC2 do Airflow e o gateway do Power BI.

  5. Servidor do Airflow (EC2)

    • Amazon Linux 2023 ARM64, t4g.large, disco gp3 30 GB.
    • Papel IAM com permissão de gravar no bucket e de usar o Session Manager (acesso ao terminal sem abrir a porta SSH).
    • Instalar Docker, o plugin Compose e o git; clonar o repositório.

  6. Ajustes do projeto para produção

    • BRONZE_URI=s3://<bucket>/bronze, WAREHOUSE_DSN apontando para o RDS com sslmode=require.
    • Um docker-compose.prod.yml sem o serviço warehouse local.
    • Remover SIMPLE_AUTH_MANAGER_ALL_ADMINS e criar usuários com senha para a interface do Airflow, acessada por túnel do Session Manager.
    • Aviso por e-mail quando a DAG falhar (Amazon SES).

  7. Levar os dados que já existem

    • pg_dump do banco local e pg_restore no RDS (schemas raw_b2click e gold).
    • aws s3 sync data/bronze s3://<bucket>/bronze para o histórico de arquivos.
    • Recarregar pela API também funciona, mas respeitando o limite: cerca de 5 chamadas por endpoint para cada mês de histórico.

  8. Rodar em paralelo e validar

    • Disparar a DAG b2click_diario na AWS e comparar os totais do gold com o banco local (litros, faturamento, aferições por posto).
    • Atenção ao limite da API: local e nuvem rodando no mesmo horário dividem as 10 chamadas/hora. Mude o horário de uma delas durante o teste.

  9. Power BI

    • Instalar o gateway de dados na máquina Windows escolhida e cadastrar a fonte PostgreSQL do RDS.
    • Trocar o servidor do relatório de localhost:5433 para o endereço do RDS, publicar no Power BI Service e agendar a atualização para 05:00.

  10. Desligar o ambiente local

    • Depois de uma semana sem divergências, pausar as DAGs no PC e parar o Docker local.
    • Revisar a primeira fatura e decidir sobre o compromisso de 1 ano.

Decisões para a equipe

Qual opção?Para começar barato e já: D (AWS liga/desliga, ≈ US$ 25). Para o menor custo de longo prazo, sem servidor e sem gateway: E (Google BigQuery), aceitando 2–3 dias de adaptação. B vale se o banco precisar ficar disponível o dia todo.
Onde fica o gateway do Power BI?Uma máquina da empresa sempre ligada (grátis) ou uma EC2 Windows (≈ US$ 43/mês, mais estável).
Servidor ligado 24 h ou só na carga?Ligado 24 h no início, para facilitar o acompanhamento. Avaliar o liga-desliga depois de estabilizar.
Relatórios que chamam a API do B2Click diretoMigrá-los para ler do banco libera a cota de 10 chamadas/hora para o pipeline e reduz o uso do token.
